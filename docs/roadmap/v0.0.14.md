# paperwars.io: Version 0.0.14 Development Plan

**Development stage:** Private Playable Alpha
**Release type:** Presentation and first-launch milestone
**Release theme:** Menus, Settings and Branding: a polished path from the URL into the air
**Builds on:** [v0.0.13](v0.0.13.md) (audio and music revamp)
**Followed by:** [v0.0.15](v0.0.15.md) (economy and content depth)

Part of the [roadmap to v0.1.0](README.md).

---

## Overview

The game now has a finished world (v0.0.11), a consistent interface (v0.0.12) and a complete soundscape (v0.0.13), on a persistent multiplayer server reachable from the internet (v0.0.10). What a player sees before and around gameplay is still functional rather than finished.

Today, the browser tab is titled `paperwars.io` with no icon. Single-player opens straight into the world. Multiplayer is reached through `?mp` or Menu, then `src/mp/Lobby.ts`: choose a name (stored in `localStorage`), quick join, create or join a classroom, then claim a desk on the claim map. Settings are spread across the pause menu in `src/ui/Menus.ts` (graphics presets, outlines and lines from `src/render/GraphicsSettings.ts`, HUD size) and the audio panel added in v0.0.13. There is no main menu, no logo, no loading screen beyond the asset progress from v0.0.11, no rebinding, no credits and few dedicated error screens.

Version 0.0.14 completes everything a player touches outside a sortie and gives the game its identity.

The release has five central objectives:

1. Implement the final logo, wordmark and brand assets throughout the game and the browser.
2. Build the main menu and rebuild the multiplayer lobby on the v0.0.12 design system.
3. Provide a complete settings screen, including control rebinding for keyboard and controller.
4. Add loading screens, transitions and clear error states.
5. Deliver a first-launch experience in which a newcomer is flying within about one minute.

Preserve:

- The PlayCanvas, TypeScript and browser-based architecture, and the DOM-over-canvas UI built in v0.0.12.
- The authoritative Node and Colyseus server and the persistent identity, invitation and reconnection rules from v0.0.10.
- Every existing feature and its tests.

Do not expand scope. Public accounts, matchmaking and moderation belong to v0.0.19. New gameplay is not part of this version.

## 1. Branding

**Priority:** Critical
**Goal:** paperwars.io has a recognisable identity everywhere it appears.

### A. Brand assets

| Asset | Use |
|---|---|
| Logo (full) | Main menu, loading screen, credits |
| Wordmark | Header, compact placements |
| Symbol / mark | Favicon, app icon, small placements |
| Favicon set | Browser tab, bookmarks, home screen icons at standard sizes |
| Social preview image | Link previews when the URL is shared |
| Colour palette | Reconciled with the v0.0.12 tokens |
| Logo sting | Short audio identity for the logo (using v0.0.13's system) |

### B. Requirements

- Assets are vector where possible, with raster exports at required sizes.
- The page title, meta description, Open Graph and similar tags are set in `index.html`.
- The logo works on light and dark backgrounds and at small sizes.
- Brand usage notes (clear space, minimum size, colours) are documented in `docs/`.
- Placeholder branding is removed everywhere.

## 2. Main Menu

**Priority:** Critical
**Goal:** A welcoming front door that gets players into the game quickly.

### A. Layout and options

| Option | Behaviour |
|---|---|
| Play / Continue | Rejoins the player's persistent world and territory directly (v0.0.10 identity) |
| Join with code | Enter or paste an invite code |
| Single player | The existing single-player game |
| How to play | Short visual guide: controls for the active device, the core loop |
| Settings | The full settings screen |
| Feedback | Opens the feedback log from v0.0.10 |
| Credits | Credits and attributions |

### B. Background

- An animated classroom scene rendered by the game itself: a slow camera fly-through over the territories, paper planes drifting past, using the v0.0.11 assets.
- Lightweight: a reduced version on the Low graphics preset; static on reduced motion.
- The world loads behind the menu so that entering play is fast.

### C. Requirements

- Fully navigable by controller, keyboard and mouse using the v0.0.12 focus system.
- Menu music from v0.0.13.
- The game version and server status are visible in a corner.

## 3. Multiplayer Lobby

**Priority:** Critical
**Goal:** Rebuild the lobby so joining, inviting and returning are obvious.

### A. Screens

Rebuild `src/mp/Lobby.ts` on the design system:

- **World list:** world name, player count and capacity, ping, whether the player already owns a territory there, online friends (where known).
- **Invite codes:** create a world, show and copy its invite code or link, join by code.
- **Claim map:** the existing classroom claim map, restyled, showing themes, landmarks, owners, online and protected status.
- **Reconnect:** if the player has an active seat or territory, offer to rejoin immediately; show the grace period remaining after a disconnect.
- **Room admin (developer):** create and configure a private world, see connection status, recover from common room errors, as introduced in v0.0.10.

### B. Requirements

- Names are validated and remain separate from identity (v0.0.10).
- Refresh is automatic, with a manual refresh option.
- Ping is measured and shown with a quality indicator (icon and number, not colour alone).
- Full worlds, closed worlds and version mismatches are explained clearly.

## 4. Settings

**Priority:** Critical
**Goal:** All settings in one complete, controller-friendly screen.

### A. Categories

| Category | Settings |
|---|---|
| Graphics | Preset (Low / Medium / High), outlines, line weight, shadows, resolution scale, antialiasing, frame-rate cap, field of view |
| Audio | Per-bus volumes and mutes, tab-hidden mute, mono (from v0.0.13) |
| Controls: keyboard and mouse | Rebinding, mouse sensitivity, inversion |
| Controls: controller | Rebinding, stick dead zones, response curves, sensitivity, inversion, camera sensitivity, recentering, vibration (if supported) |
| Interface | HUD size, text scale, key hints, first-time tips reset, ultrawide safe area |
| Accessibility | Colour-blind palette, reduced motion, subtitles and sound indicators, high-contrast panels |
| Network | Server region (where available), show ping, connection diagnostics |
| Account / profile | Display name, identity information and device linking as supported by v0.0.10 |

### B. Rebinding

- Built on the unified input-action layer from v0.0.11.
- Rebind any action for keyboard, mouse and controller separately.
- Conflict detection with clear resolution.
- Reset per category and reset all.
- Hints across the game update immediately (v0.0.12 device-aware hints).

### C. Storage and behaviour

- Per-computer settings (graphics) remain per computer, as `GraphicsSettings.ts` does today.
- Per-player settings (controls, interface, accessibility, audio) are stored with the persistent player profile so they follow the player.
- Changes apply immediately where possible, with a revert timer for risky graphics changes.
- Settings are reachable from the main menu and the pause menu.

## 5. Loading Screens and Transitions

**Priority:** High
**Goal:** No blank screens and no jarring cuts.

### A. Loading screens

- Real progress (assets, audio, world state, connection), extending the v0.0.11 loading feedback.
- Tips about controls and the core loop, matching the active input device.
- Branded art in the sketchbook style.
- Clear stages: connecting, loading world, restoring your territory.

### B. Transitions

- Between main menu, lobby, desk, flight, base management and results.
- Short, paper-themed (page turn, fold, slide), using the v0.0.12 motion tokens.
- Instant cuts on reduced motion.

---

## 6. First-Launch Experience

**Priority:** Critical
**Goal:** A newcomer goes from opening the URL to flying in about one minute.

### A. Flow

1. Logo and loading.
2. Choose a display name.
3. Short control check for the detected device (move the stick or mouse, press fire).
4. Enter the world: claim a territory (multiplayer) or start at the home desk (single player).
5. Offer the interactive tutorial from v0.0.8 / v0.0.11, skippable.
6. Launch a Dart.

### B. Requirements

- No account creation is required at this stage (public accounts are v0.0.19).
- Returning players skip directly to Play / Continue.
- The flow is measured: time from page open to first take-off is logged locally and in the feedback log during testing.
- Every step works by controller only and by keyboard and mouse.

## 7. Error States

**Priority:** High
**Goal:** Every common failure has a clear, friendly screen with a next step.

| Situation | Message intent | Action |
|---|---|---|
| Server unavailable | The classroom is closed right now | Retry, single player |
| Connection lost | Trying to reconnect, with grace period | Wait, retry, return to menu |
| World full | This classroom is full | Choose another world |
| Invalid or expired invite | Invite not found | Enter another code |
| Access denied | Not invited | Explanation of private alpha access |
| Version mismatch | A newer version is available | Reload |
| Save restoration problem | Your territory could not be restored yet | Retry, report |
| Controller not recognised | Controller mapping unknown | Use generic mapping, open controller settings |
| Audio blocked | Click to enable sound | Enable |
| WebGL unavailable | This browser cannot run the game | Help link |

- Messages follow the short-phrase rules from GDD §15, with details on demand.
- Errors are logged for the feedback log and server logs where relevant.

## 9. Testing and Verification

**Priority:** Critical

### A. Automated

- Unit tests for rebinding, conflict detection and settings persistence.
- Tests for invite code creation, validation and expiry.
- Tests for error-state routing (each failure leads to the right screen).
- Existing tests continue to pass.

### B. Browser

- Screenshots of the main menu, lobby, settings, loading screens, credits and each error state at 1080p, 4K and 21:9.
- Social preview validated with a link-preview checker.

### C. Hands-on

- A first-launch run by someone who has not played before (the invited friend on a fresh browser profile), timed from URL to take-off. Target: about one minute.
- Controller-only and keyboard-only walkthroughs of every new screen.
- Simulated failures: server down, connection cut, world full, wrong invite code, old client version.
- Rebinding a control and verifying in-game behaviour and hints.

## 12. AI Agent Implementation Strategy

**Priority:** Critical

| Phase | Focus |
|---|---|
| 1 | Audit every screen outside gameplay and every setting; record a baseline including time to first take-off |
| 2 | Brand assets integrated: favicon, title, social preview, logo placements |
| 3 | Main menu and animated background; developer checkpoint |
| 4 | Lobby rebuild: world list, invite codes, claim map, reconnect |
| 5 | Settings screen and rebinding |
| 6 | Loading screens, transitions, error states |
| 7 | First-launch flow and credits |
| 8 | Testing, first-launch timing with the invited friend, fixes; developer checkpoint |

Rules:

- Work in reviewable increments.
- Do not mark a phase complete because the code compiles; verify in the browser, with tests, and by controller.
- Preserve every earlier feature, including single-player access.
- Stop at the developer checkpoints after phases 3 and 8.

## 13. Definition of Done

- [ ] The logo, wordmark, favicon set and social preview are implemented; no placeholder branding remains.
- [ ] The main menu exists with an animated classroom background and all listed options.
- [ ] The lobby shows worlds with player counts and ping, supports invite codes and offers reconnect.
- [ ] The settings screen covers every listed category and is reachable from the main and pause menus.
- [ ] Keyboard, mouse and controller rebinding works, with conflict detection and immediate hint updates.
- [ ] Per-player settings persist with the player profile; per-computer settings stay per computer.
- [ ] Loading screens show real progress and tips; transitions connect every mode.
- [ ] Every listed error state has a clear screen and next step.
- [ ] Credits and attributions are complete.
- [ ] A newcomer reaches first take-off in about one minute, measured.
- [ ] Every new screen is fully usable by controller only and by keyboard and mouse.
- [ ] All existing tests and the new tests pass.
- [ ] The developer has approved the branding and main menu and completed the first-launch test.

---

## Final Design Principle

The first minute decides whether someone stays. paperwars.io should open with a clear identity, explain itself without words, and put a paper plane in the player's hands almost immediately, while making every return visit as simple as pressing Continue.
